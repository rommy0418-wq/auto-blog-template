편집 정정 — 2026년 9월 16일. 이전 제목과 본문의 경력·현장 경험 서술은 운영자가 제공한 경험 기록에 근거하지 않았습니다. 물류기업과 에이전시의 가상 성과도 실제 실적으로 해석되지 않도록 삭제했습니다. 이 글은 특정인의 경험담이 아닌, AI 업무 도입 시 책임과 승인 절차를 정하기 위한 실무 설계안입니다.

AI를 업무에 넣으면 결과를 만드는 사람과 결과에 책임지는 사람이 달라질 수 있습니다. 초안을 빨리 생성했더라도 잘못된 내용이 고객에게 전달되거나 원본 자료를 찾을 수 없다면 업무가 개선됐다고 판단하기 어렵습니다. 도구를 추가하기 전에 다음 문서를 한 장으로 작성해 보세요.

업무 인계 명세: 누가 무엇을 확인하는가

항목정할 내용빠졌을 때 생기는 문제
시작 조건어떤 요청이 들어오면 작업을 시작하는지중복 요청을 새 업무로 처리
입력 책임자최신 원본과 사용 가능한 정보 범위를 지정하는 사람폐기된 자료로 답변 작성
AI 작업 범위요약·분류·초안 중 허용할 작업과 금지할 작업초안 작성이 외부 발송으로 확대
검수 책임자내용과 근거를 대조할 담당자 및 부재 시 대체자검수자가 없어 미검토 결과가 쌓임
완료 조건어떤 승인과 기록이 있어야 완료로 표시하는지생성 완료를 업무 완료로 오인
예외 처리입력 부족·오류·중복·서비스 중단 시 보류 위치실패 작업이 조용히 누락

설계 예시: 제안서 초안 업무의 책임 나누기

다음은 실제 고객 프로젝트가 아닌 구성 예시입니다. 영업 담당자가 고객 요청과 승인된 서비스 설명서를 준비하고, AI는 제안서 목차와 초안을 작성합니다. 서비스 담당자는 제공 범위를, 견적 책임자는 가격과 일정의 승인 여부를 확인합니다. 최종 발송은 권한 있는 담당자가 합니다.

고객이 “다음 주까지 가능하죠?”라고 질문했지만 확정 일정이 없다면 초안에는 ‘일정 확인 필요’로 남깁니다. AI가 일정이나 할인 조건을 채우면 검수 실패입니다. 영업 담당자가 AI 결과를 편집했더라도 가격 승인까지 대신한 것으로 취급하지 않습니다.

상태를 나누면 자동화의 경계가 보입니다

  1. 접수: 요청 번호와 원본 자료 위치를 기록합니다.
  2. 작성 중: AI가 결과를 만들되 외부 발송 권한은 갖지 않습니다.
  3. 검수 대기: 검수자가 입력 자료와 초안을 함께 확인합니다.
  4. 수정 필요: 잘못된 부분과 수정 이유를 남기고 재검토합니다.
  5. 승인: 승인자가 결과 버전과 승인 시점을 기록합니다.
  6. 전달 완료: 실제 전달 결과를 확인한 뒤 완료 처리합니다.

승인 후 내용을 고쳤다면 다시 검수 대기로 돌리는 규칙을 제안합니다. 이전 버전의 승인으로 새 버전을 발송하면 승인 기록이 있어도 최종 내용의 검수를 입증할 수 없기 때문입니다.

자동화에 앞서 해볼 예외 시험

  • 필수 첨부 자료가 없으면 임의로 작성하지 않고 보류하는가
  • 같은 요청을 다시 넣어도 중복 발송하지 않는가
  • 검수자가 부재할 때 미승인 결과가 자동 전달되지 않는가
  • 승인 후 가격이나 납기가 바뀌면 기존 승인이 해제되는가
  • 외부 도구가 중단돼도 작업 상태와 원본이 남아 수동으로 이어갈 수 있는가

확대 여부를 판단할 회의 기록

생성 속도만 보지 말고 원본 준비, 검수, 수정, 예외 처리에 든 시간을 함께 기록하세요. 수정 사유도 ‘틀림’ 한 칸으로 끝내지 말고 근거 부족·조건 누락·금지된 약속·형식 오류로 나누면 다음 개선 대상을 찾기 쉽습니다.

회의록에는 ‘확대’, ‘범위 유지’, ‘중단’ 중 결정과 이유, 미해결 오류, 다음 검토일, 책임자를 남깁니다. 실제 기록이 없으면 효과 수치를 적지 말고 아직 측정하지 않았다고 쓰세요. 실행 기록 양식은 AI 업무 시험 운영 가이드에서 참고할 수 있습니다.
