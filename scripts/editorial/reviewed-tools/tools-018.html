가상 과제: 빈 문의를 막기

요구를 ‘공백만 있는 문의는 전송하지 않고 안내를 보여 준다’로 정합니다. AI에 사이트 전체를 고치라고 하기보다 관련 입력과 검증 범위를 찾고 변경 내용을 설명하도록 요청합니다. 실제 개인정보와 비밀키가 담긴 파일을 무심코 공유하지 마세요.

시험 입력기대 결과
빈 문자열전송 중지와 안내
공백만 있는 문자열전송 중지와 안내
정상 문의기존 흐름 유지
허용 길이를 넘는 입력정해진 오류 처리
잘못된 형식의 직접 요청서버에서도 거부

위 표는 시험 설계이지 실제 코드가 통과했다는 결과가 아닙니다. 화면에서 버튼이 막혀도 서버에 직접 요청하면 저장되는지 확인해야 합니다. 검증 방법을 알 수 없다면 기술 담당자의 도움을 받습니다.

변경 전후 확인

  • 원본과 변경 이력을 복구 가능한 상태로 둡니다.
  • 요청하지 않은 파일·의존성·권한 변경을 확인합니다.
  • 테스트를 실제 실행했는지와 결과를 구분합니다.
  • 실패한 시험을 숨기거나 단순히 제거하지 않습니다.
  • 운영 배포 전 비밀정보·접근 통제·오류 처리를 검토합니다.

AI가 제안한 명령을 이해하지 못한 채 실행하지 마세요. 특히 파일 삭제, 원격 전송, 데이터베이스 변경, 공개 배포는 대상과 영향 범위를 확인해야 합니다. 의존성을 추가할 때도 목적과 신뢰할 수 있는 배포 경로를 확인합니다.
