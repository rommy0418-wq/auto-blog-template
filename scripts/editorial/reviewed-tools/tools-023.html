가상 기대 결과

가상 사용자 A가 작성한 문의를 사용자 B가 보려고 하면 접근이 거부돼야 합니다. 목록에서 행을 숨기는 것만으로 데이터 접근이 막혔다고 가정하지 마세요. 실제 도구의 보안 기능과 데이터 전달 방식을 확인하고 시험해야 합니다. 이 표는 보안 인증이나 실제 실행 결과가 아닙니다.

AI 기능을 붙이기 전에

  • 기본 입력·저장·수정·삭제가 올바르게 동작하는지 확인합니다.
  • 외부 AI로 전달할 필드와 보관 조건을 정합니다.
  • 키와 비밀정보를 공개 화면이나 클라이언트에 두지 않습니다.
  • 실패 응답을 성공처럼 저장하지 않습니다.
  • 사용량·청구·서비스 중단 경로를 확인합니다.

문제가 생길 때 데이터를 내보내고 다른 방식으로 운영할 수 있는지도 봅니다. 서비스나 플랜 변경으로 필요한 기능을 사용할 수 없게 될 가능성도 계약 검토 항목입니다. ‘코딩 없음’과 ‘운영 책임 없음’을 혼동하지 않습니다.

공개 여부 결정

처음에는 비민감 가상 자료와 제한된 시험 사용자로 확인합니다. 보안·개인정보·실제 결제 기능의 검증을 할 수 없다면 전문 지원을 받거나 그 기능을 제외하세요. 최종 보고에는 구현한 화면, 실제 통과한 시험, 미검증 항목을 구분합니다.

기능 데모를 실제 서비스 납품이나 고객 성과로 소개하지 않습니다. 공개할 때는 이용자에게 실제 제공 범위와 문의·오류 대응 경로를 명확히 안내해야 합니다.
