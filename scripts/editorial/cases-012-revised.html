편집 정정 — 2026년 9월 16일. 이전 글의 개인 경력 서술과 가상 컨설팅 성과, 일반화된 수익 기대를 삭제했습니다. 확인하지 않은 자격증 목록을 현재 취득 추천처럼 제시하지 않습니다. 이 글은 특정인의 경력담이나 자격·수입 보장이 아닌, AI 업무 개선 역량을 결과물로 보여주는 포트폴리오 설계입니다.

AI 도구 이름을 많이 나열하는 것과 고객 업무를 개선할 수 있음을 보여주는 것은 다릅니다. 처음에는 실제 고객을 꾸며내지 말고 공개 가능한 연습 자료로 작은 작업을 정하고, 문제 정의부터 실패 분석까지 남기는 방식을 제안합니다.

1. 포트폴리오의 주장 범위를 정합니다

표시뜻필요한 기록
설계안아직 실행하지 않은 절차 제안범위·가정·검증 계획
개인 실습자신이 만든 시험 환경에서 실행입력·설정·출력·실행 기록
현장 시험허가된 실제 업무에서 제한적으로 시험승인 범위·측정 조건·비공개 정보 처리
운영 사례실제 사용과 후속 관리 기록이 있음운영 기간·장애·변경·성과의 근거

실습을 고객 프로젝트로 쓰거나 설계안을 실측 성공 사례로 바꾸지 않습니다. 공개 허락이 없는 고객명과 업무 자료는 넣지 않으며, 이름을 지운 자료라도 내용 공개가 허용되는지 별도로 확인합니다.

2. 작은 과제 하나로 역량을 보여줍니다

예를 들어 공개된 행사 안내문에서 날짜·장소·미확정 사항을 추출하는 내부 실습을 선택할 수 있습니다. 목표는 화려한 화면이 아니라 잘못된 날짜를 만들지 않고 원문 근거를 제시하는지 확인하는 것입니다. 행사 신청이나 메일 발송은 제외합니다.

실습 명세: 입력은 사용 가능한 안내문 / 출력은 날짜·장소·근거 문장·확인 필요 항목 / 금지는 미정 정보 추정과 외부 발송 / 검수는 사람이 원문 대조 / 완료 조건은 합의한 시험 질문과 실패 결과 기록.

날짜가 없는 문서, 서로 다른 버전의 날짜, 장소가 아직 정해지지 않은 문서를 시험에 포함합니다. 정상 문서 한 개만 성공한 장면으로 모든 안내문을 처리할 수 있다고 주장하지 않습니다.

3. 결과물 묶음에 넣을 문서

  • 문제 정의: 누가 어떤 오류나 재작업을 겪는지, 실제 조사인지 실습 가정인지
  • 범위표: 허용 입력·출력, 제외 업무와 책임자
  • 자료 설명: 출처·사용 범위·준비 방식·빠진 자료
  • 시험표: 입력별 기대 결과, 실제 출력, 통과·실패와 이유
  • 비교 기록: 기존 방식과 같은 완료 기준에서 든 총시간
  • 인수인계: 실행·중단·복구·변경 시 재시험 방법

AI가 만든 평가표를 그대로 정답으로 삼지 말고 기대 결과를 직접 확인합니다. 실패를 지우는 대신 무엇을 바꿨고 어떤 입력을 다시 시험했는지 남기면 검토자가 작업의 한계와 판단 과정을 볼 수 있습니다.

4. 역량 부족을 구체적인 학습 과제로 바꿉니다

발견한 문제다음 학습 과제
고객 요구를 한 문장으로 정의하지 못함업무 인터뷰와 완료 조건 작성 연습
입력 정리·권한 확인을 빠뜨림자료 목록·접근 범위·출처 기록 연습
출력 오류를 분류하지 못함정답 기준과 실패 유형 설계 연습
도구 장애에 대응하지 못함로그·재시도 제한·수동 복구 연습

자격 과정은 이런 학습 과제에 필요한 내용을 제공하는지 기준으로 검토할 수 있습니다. 과정의 현재 운영 여부, 응시 조건과 갱신은 발급 기관의 최신 안내에서 확인하세요. 이 글은 어떤 자격이 법적으로 필수인지 또는 취득하면 일을 얻는지 판단하지 않습니다.

5. 제안서에 수익 약속 대신 범위를 적습니다

유료 업무를 제안한다면 산출물, 고객이 준비할 자료, 검수 기준, 수정 범위, 운영 지원과 제외 업무를 구분합니다. 아직 실측하지 않은 시간 절감이나 매출 증가를 확정 약속으로 쓰지 않습니다. 계약·세무·규제 판단은 필요할 때 해당 전문가와 별도로 확인해야 합니다.
